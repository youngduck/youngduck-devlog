## 4.1 서브쿼리

- 서브쿼리는 반드시 괄호로 감싸서 표현

- 들어가는 위치에 따른 구분, **스인중**

| 종류            | 설명                                                  |
| --------------- | ----------------------------------------------------- |
| 스칼라 서브쿼리 | SELECT문의 컬럼 입력 위치에 존재                      |
| 인라인 뷰       | FROM절의 테이블 입력 위치에 존재                      |
| 중첩 서브쿼리   | WHERE절, HAVING절의 컬럼 또는 테이블 입력 위치에 존재 |

- 메인쿼리의 컬럼 사용 여부에 따른 구분, **연비**

| 종류            | 설명                                            |
| --------------- | ----------------------------------------------- |
| 연관 서브쿼리   | 서브쿼리가 메인쿼리의 컬럼을 사용하는 경우      |
| 비연관 서브쿼리 | 서브쿼리가 메인쿼리의 컬럼을 사용하지 않는 경우 |

### 4.1.1 스칼라 서브쿼리

- SELECT, ORDER BY등에 들어가는 서브쿼리
- 컬럼이 입력되는 위치에 삽입되므로 서브쿼리의 결과는 하나의 컬럼만을 가져야함

### 4.1.2 인라인 뷰

- FROM 절의 테이블이 입력되는 위치에 들어가는 서브쿼리
- VIEW와 같이 쿼리실행시 생성되는 동적 테이블이라고 볼수 있음
- 테이블의 일부분만 불러와 사용함으로써 비교횟수를 줄이는 이점 존재

#### 테이블과 뷰의 차이

| 구분        | 테이블(Table)                          | 뷰(View)                                                |
| ----------- | -------------------------------------- | ------------------------------------------------------- |
| 개념        | 실제 데이터를 저장하는 물리적 객체     | 하나 이상의 테이블로부터 유도된 가상 테이블             |
| 데이터 저장 | 실제 데이터를 저장함                   | 데이터를 저장하지 않고 쿼리(정의)만 저장함              |
| 생성 방식   | 정적 생성                              | 동적 생성                                               |
| 인덱스 생성 | 인덱스 생성 가능                       | 원칙적으로 인덱스 생성 불가 (기반 테이블의 인덱스 사용) |
| CRUD        | 삽입/조회/수정/삭제 모두 자유롭게 가능 | 조회는 자유로우나 삽입/수정/삭제는 제약이 존재          |

#### 뷰의 특징

| 특징   | 설명                                                                                      |
| ------ | ----------------------------------------------------------------------------------------- |
| 편리성 | 복잡한 쿼리를 뷰로 정의해두면 간단하게 재사용할 수 있어 SQL 작성이 편리함                 |
| 보안성 | 특정 컬럼이나 행만 노출하도록 정의할 수 있어 민감한 데이터를 숨겨 보안을 강화할 수 있음   |
| 독립성 | 기반 테이블의 구조가 변경되어도 뷰의 정의만 유지하면 되므로 논리적 데이터 독립성을 제공함 |

### 4.1.3 중첩 서브쿼리

- WHERE절,HAVING절에 들어가는것을 지칭
- 단일행, 다중행, 다중컬럼같이 다양한 반환값을 가짐
- 중첩 서브쿼리의 경우 메인쿼리와 연관성이 있으면 연관서브쿼리, 없으면 비연관 서브쿼리라 함

## 4.2 집합연산자

- JOIN과달리 특정한 기준키 없이 합집합, 교집합 연산을 수행하므로 두테이블의 컬럼구성(스키마)가 동일해야함
- 스키마 구성은 동일하나 컬럼의 이름이 다를 경우 첫번째 테이블의 이름을 따름

### 4.2.1 UNION ALL / UNION

- 합집합 연산 수행
- UNION ALL : 중복 포함
- UNION : 중복 제거, 1건만

### 4.2.2 INTERSECT

- 교집합 연산 수행

### 4.2.3 MINUS / EXCEPT

- 차집합 연산 수행

## 4.3 그룹함수

- GROUP BY 절에 따른 결과에 대해서 그룹 별로 연산을 수행하는 함수

### 4.3.1 ROLLUP

- GROUP BY 절에 들어가는 컬럼을 대상으로 하위 그룹핑을 수행하는 함수
- 소계와 총계를 구할 때 사용
- ROLLUP(부서명,입사연도) 시 부서명,입사연도 갯수, 부서 갯수, 전체 총 갯수가 나옴

### 4.3.2 CUBE

- ROLLUP은 1차원적인 하위그룹핑만 수행하지만 CUBE는 조합가능한 모든 경우로 그룹핑 수행
- 인자 1개일경우 ROLLUP과 동일
- 인자 두개이상일 경우 (부서명,입사연도) -> (부서명) -> (입사연도) -> (전체)

### 4.3.3 GROUPING SETS

- 그룹핑할 대상을 지정하는 함수
- 인자로 ROLLUP,CUBE를 넣을 수 있음
- 개별 소계

### 4.3.4 GROUPING

- ROLLUP, CUBE, GROUPING SETS와 함께 사용하여 소계에 해당하는행, 그렇지않은행 구분을 가능하게 해줌
- 소계의 해당하는행은 1, 그렇지않은 행 0 반환, CASE문에 사용

## 4.4 윈도우함수

- 행과행간의 관계를 나타내는 연산을 쉽게 하기 위한 함수
- GROUP BY의 경우 각행으 ㄹ대상으로 연산 수행 후 새로운 구성을 만들지만, 윈도우 함수는 각 행의 기존 구성을 유지한 상태로 해당 행에 대해서 새로운 값을 추가 또는 기존의 값을 변경함
- 대표적으로 RANK 함수, 모든 윈도우 함수는 OVER 키워드와 함께 사용

### 4.4.1 순위함수

| 함수이름   | 설명                                                           | 예         |
| ---------- | -------------------------------------------------------------- | ---------- |
| RANK       | 동일 순위를 같은 값으로 부여하고, 그 다음 순위는 건너뜀        | 1, 2, 2, 4 |
| DENSE_RANK | 동일 순위를 같은 값으로 부여하고, 그 다음 순위는 건너뛰지 않음 | 1, 2, 2, 3 |
| ROW_NUMBER | 동일 값이라도 중복 없이 고유한 순번을 부여함                   | 1, 2, 3, 4 |

### 4.4.2 집계함수

- OVER절을 사용해서 파티션 별로 집계하거나 누적 집계를 할 수 있음

| 함수이름 | 설명                              |
| -------- | --------------------------------- |
| COUNT    | 파티션 내 행의 개수를 반환함      |
| SUM      | 파티션 내 값들의 합계를 반환함    |
| AVG      | 파티션 내 값들의 평균을 반환함    |
| MIN      | 파티션 내 값들 중 최솟값을 반환함 |
| MAX      | 파티션 내 값들 중 최댓값을 반환함 |

- PARTITION BY로 나눈 파티션(그룹) 단위로 집계하며, 원래의 행 구성은 그대로 유지됨

```sql
SELECT 사원명, 부서명, 급여,
       SUM(급여) OVER (PARTITION BY 부서명) AS 부서합계
FROM 사원;
```

| 사원명 | 부서명 | 급여 | 부서합계 |
| ------ | ------ | ---- | -------- |
| 김     | 영업   | 100  | 300      |
| 이     | 영업   | 200  | 300      |
| 박     | 개발   | 150  | 150      |

- 부서명을 기준으로 파티션이 나뉘어, 영업 파티션(김·이)의 합계 300, 개발 파티션(박)의 합계 150이 각 행마다 표시됨

### 4.4.3 행 순서함수

| 함수이름    | 설명                                           |
| ----------- | ---------------------------------------------- |
| FIRST_VALUE | 파티션 내 정렬 기준상 첫 번째 행의 값을 반환함 |
| LAST_VALUE  | 파티션 내 정렬 기준상 마지막 행의 값을 반환함  |
| LAG         | 파티션 내 현재 행 기준 이전 행의 값을 반환함   |
| LEAD        | 파티션 내 현재 행 기준 이후 행의 값을 반환함   |

### 4.4.4 비율함수

- 백분율등 비율 연산

| 함수이름        | 설명                                                                            |
| --------------- | ------------------------------------------------------------------------------- |
| CUME_DIST       | 파티션 내에서 현재 행의 누적 백분율(0 초과 1 이하)을 반환함                     |
| PERCENT_RANK    | 파티션 내에서 현재 행의 상대적 순위를 백분율(0 이상 1 이하)로 반환함, 0부터시작 |
| NTILE           | 파티션 내 행들을 지정한 개수의 그룹으로 나누고 각 행의 그룹 번호를 반환함       |
| RATIO_TO_REPORT | 파티션 내 전체 합계 대비 현재 행 값의 비율을 반환함                             |

## 4.6 계층형 질의와 셀프 조인

- 계층형 데이터 : 하나의 테이블 안에서 행과 행 사이에 부모-자식 관계가 존재하는 데이터 (예: 사원-관리자, 조직도, 게시판 답글)
- 각 행은 자신의 부모를 가리키는 컬럼(예: 관리자 사번)을 가지며, 이를 따라 올라가거나 내려가며 계층 구조를 표현함
- 이러한 계층 구조를 조회하는 방법으로 계층형 질의와 셀프 조인이 있음

| 구분        | 설명                                                                |
| ----------- | ------------------------------------------------------------------- |
| 계층형 질의 | START WITH, CONNECT BY 등 전용 키워드로 계층 구조를 재귀적으로 탐색 |
| 셀프 조인   | 하나의 테이블을 자기 자신과 조인하여 부모-자식 관계를 연결          |

### 4.6.1 계층형 질의

- 아래의 키워드를 사용해서 계층형 질의를 작성하면 셀프조인을 사용하지 않고 효율적인 쿼리작성 가능

| 함수/키워드         | 설명                                                      |
| ------------------- | --------------------------------------------------------- |
| START WITH          | 계층 구조 탐색의 시작점(최상위 루트) 행을 지정함          |
| CONNECT BY          | 부모-자식 연결 조건을 지정하여 계층을 따라 탐색함         |
| PRIOR               | CONNECT BY절에서 부모 행을 가리키는 키워드                |
| LEVEL               | 현재 행의 계층 깊이를 반환함 (루트는 1)                   |
| CONNECT_BY_ROOT     | 현재 행이 속한 계층의 최상위 루트 값을 반환함             |
| CONNECT_BY_ISLEAF   | 현재 행이 최하위(잎) 노드이면 1, 아니면 0을 반환함        |
| SYS_CONNECT_BY_PATH | 루트부터 현재 행까지의 경로를 지정한 구분자로 이어 반환함 |
| NOCYCLE             | 계층 구조에 순환이 있어도 오류 없이 탐색을 계속하게 함    |
| ORDER SIBLINGS BY   | 같은 부모를 가진 형제 행들 사이의 정렬 순서를 지정함      |

### 4.6.2 셀프 조인

- 하나의 테이블을 조인
- 계층의 깊이가 너무길어지면 셀프조인보다는 계층형 질의를 사용해서 해결하는것이 좋음

## 4.7 PIVOT절과 UNPIVOT절

- 헹과열을 전환하여 테이블을 재구성 하는 것
- 행열을 바꾸는 관점에따라 피벗,언피벗 구분

### 4.7.1 PIVOT절

- 행을 열로 바꿈
- 각 행 속성값들이 컬럼 헤더가되고, 속성값이 재배치

### 4.7.2 UNPIVOT절

- 열을 행으로 바꿈
- 컬럼 헤더들이 한컬럼의 속성값들이 됨

## 4.8 정규표현식

- 문자열의 패턴을 표현하는 형식 언어로, 복잡한 문자열 검색·치환·추출을 간결하게 처리할 수 있음
- LIKE만으로는 표현하기 어려운 정교한 패턴 매칭에 사용

| 함수           | 설명                                                        |
| -------------- | ----------------------------------------------------------- |
| REGEXP_LIKE    | 문자열이 패턴과 일치하는지 여부를 반환 (주로 WHERE절에 사용) |
| REGEXP_REPLACE | 패턴과 일치하는 부분을 다른 문자열로 치환                    |
| REGEXP_SUBSTR  | 패턴과 일치하는 부분 문자열을 추출                          |
| REGEXP_INSTR   | 패턴과 일치하는 부분의 시작 위치를 반환                     |
| REGEXP_COUNT   | 패턴과 일치하는 횟수를 반환                                 |

- 주요 메타문자

| 메타문자 | 설명                              |
| -------- | --------------------------------- |
| ^        | 문자열의 시작                     |
| $        | 문자열의 끝                       |
| .        | 임의의 한 문자                    |
| \*       | 앞 문자가 0회 이상 반복           |
| +        | 앞 문자가 1회 이상 반복           |
| ?        | 앞 문자가 0회 또는 1회            |
| [ ]      | 대괄호 안의 문자 중 하나          |
| \|       | OR (둘 중 하나)                   |
| { }      | 반복 횟수 지정 (예: {2,4})        |
