## 3.1 관계형 데이터베이스 개요

### 3.1.1 데이터베이스

- 데이터 : 컴퓨터로 일을 처리할때 처리 대상이 되는 것, 수집한 사실 또는 값
- 정보 : 데이터를 가공하여 유용하게 활용할 수 있게 만든 것
- 처리, 프로세싱: 가치없는 데이터를 목적에 따라 가공하여 유용한 정보로 변환하는 과정
- 데이터베이스 : 데이터를 일정한 체계에 따라 통합하여 디스크,메모리에 저장한것으로 응용프로그램에 종속적이지 않도록 일종의 미들웨어 형태로 만든 것. 데이터 처리과정의 중복서, 일관성등의 오류를 없애기 위해 등장
- 데이터베이스관리시스템(DBMS) : 데이터베이스를 구축하고 관리할 수 있는 기능을 제공하는 시스템

### 3.1.2 관계형 데이터베이스

- 1970년 E.F.Codd박사가 발표한 정규화 이론에 따라 데이터의 일관성 문제를 근본적으로 해결한 DBMS -> RDB 등장
- 2차원 구조의 행과 열로 구성된 테이블 형태로 데이터 모델을 다루며 수학적 이론을 바탕으로 연산자체를 수학적으로 최적화 할 수 있음
- SQL이라는 공통의 질의언어를 정의하여 데이터로부터 정보를 쉽게 조회, 가공, 추출하는것이 가능

### 3.1.3 TABLE

- 행과 열로 표현된 2차원 매트릭스 형태를 뜻함
- 논리적 모델링에서는 Entity, 물리적모델링에서는 테이블이라고 부름, 관계형 DB에서는 Relation이라고 부르기도함
- 컬럼 헤더 / 스키마
- 행 / 레코드 / 튜플
- 열 / 필드 / 속성

### 3.1.4 SQL

- Structured Query Language, 구조화된 질의언어
- DB구조를 정의, 데이터를 조작, 제어하는 절차적 + 비절차적 언어
- DDL : Data Definition Language, 데이터 정의 언어
  - 데이터의 구조, 스키마를 정의하는 명령어
  - ERD로 그려진 모델은 DDL과 상호 변환이 가능
  - ex ) CREATE, ALTER, DROP, RENAME, TRUNCATE
- DML : Data Manipulation Language, 데이터 조작 언어
  - 데이터를 조회,입력, 수정, 삭제 하는 명령어
  - 커밋 전에 롤백이 가능
  - ex ) SELECT, UPDATE, INSERT, DELETE, MERGE
- DCL : Data Control Language, 데이터 제어언어
  - 사용자 접근 권한과 같은 보안과 제어를 다루는 명령어
  - ex ) GRANT, REVOKE
- TCL: Transaction Control Language
  - 트랜잭션 제어 언어
  - ex ) COMMIT, ROLLBACK, SAVEPOINT

## 3.2 SELECT문

### 3.2.1 SELECT

- 데이터 조회 명령어, WHERE절을 통해 특정조건의 열 조회
- 테이블에 대한 별명(Alias)부여 가능
- SELECT문 절 실행순서 -> **F-W-G-H-S-O**

### 3.2.2 산술연산자

- 더하기, 곱하기 등 산술연산 수행
- 동일한 행에서 칼럼 대 칼럼의 연산 수행
- Null과의 산술연산 결과는 Null, 0으로나누면 에러발생

### 3.3.3 합성연산자

- ||는 합성연산자로 문자열을 연결할 때 사용용

## 3.3 함수

### 단일행 함수 vs 다중행 함수

- 단일행 함수 : 하나의 행에 대해서 연산을 수행한 후 결과를 반환, 1:M의 조인에서도 M쪽의 각각의 행에 대해서 단일행 함수를 사용가능
- 다중행 함수 : 여러 행에 대해서 연산을 수행한 후 결과를 반환, 집계함수(COUNT,SUM,AVG 등), 그룹함수(ROLLUP, CUBE), 윈도우함수(RANK, ROW_NUMBER등)등이 해당

### 3.3.1 문자함수

| 함수                 | 설명                                 |
| -------------------- | ------------------------------------ |
| LOWER / UPPER        | 소문자 / 대문자로 변환               |
| CHR(CHAR)            | ASCII 코드 → 문자 변환               |
| TRIM / LTRIM / RTRIM | 양쪽 / 왼쪽 / 오른쪽 공백(문자) 제거 |
| SUBSTR               | 문자열 일부 추출                     |
| LENGTH               | 문자열 길이 반환                     |
| REPLACE              | 특정 문자열 치환                     |

### 3.3.2 숫자함수

### 3.3.6 CASE

- 2가지 형식으로 작성가능

1. 단순 CASE 표현식 : 특정 컬럼의 값과 일치하는지 비교

```sql
SELECT ename,
       CASE deptno
            WHEN 10 THEN '인사팀'
            WHEN 20 THEN '개발팀'
            ELSE '기타'
       END AS dept_name
  FROM emp;
```

2. 검색 CASE 표현식 : WHEN절에 조건식을 직접 작성

```sql
SELECT ename,
       CASE WHEN sal >= 3000 THEN '고연봉'
            WHEN sal >= 1500 THEN '중간'
            ELSE '저연봉'
       END AS sal_grade
  FROM emp;
```

## 3.4 WHERE절

> 특정조건 만족하는 행만을 대상으로 연산 수행

### 3.4.1 비교연산자

| 구분   | 연산자  | 설명                                  |
| ------ | ------- | ------------------------------------- |
| 단일행 | =       | 같음                                  |
| 단일행 | <, <=   | 작음, 작거나 같음                     |
| 단일행 | IS NULL | NULL 여부 비교                        |
| 다중행 | IN      | 목록 중 하나라도 일치하면 참          |
| 다중행 | EXISTS  | 서브쿼리 결과가 존재하면 참           |
| 다중행 | ALL     | 목록의 모든 값과 비교하여 만족하면 참 |
| 다중행 | ANY     | 목록의 값 중 하나라도 만족하면 참     |

### 3.4.2 부정 비교연산자

| 구분   | 연산자      | 설명                      |
| ------ | ----------- | ------------------------- |
| 단일행 | !=, ^=, <>  | 같지 않음                 |
| 단일행 | IS NOT NULL | NULL이 아니면 참          |
| 다중행 | NOT IN      | 목록에 포함되지 않으면 참 |
| 다중행 | NOT EXISTS  | 서브쿼리 결과가 없으면 참 |

### 3.4.3 SQL 연산자

| 연산자          | 설명                                           |
| --------------- | ---------------------------------------------- |
| BETWEEN A AND B | A와 B 사이의 값이면 참 (A, B 포함)             |
| LIKE            | 문자열 패턴 비교 (% : 여러 문자, \_ : 한 문자) |

### 3.4.4 부정 SQL 연산자

| 연산자              | 설명                        |
| ------------------- | --------------------------- |
| NOT BETWEEN A AND B | A와 B 사이의 값이 아니면 참 |
| NOT LIKE            | 패턴과 일치하지 않으면 참   |

### 3.4.5 논리연산자

| 연산자 | 설명                          |
| ------ | ----------------------------- |
| AND    | 두 조건 모두 참이면 참        |
| OR     | 두 조건 중 하나라도 참이면 참 |
| NOT    | 조건의 결과를 반대로          |

## 3.5 GROUP BY, HAVING절

### 3.5.1 GROUP BY

- 매우 부하가 높은 연산
- WHERE,HAVING 두개다 사용해서 필터링을 할 수 있지만 WHERE절에서 해주는게 조회성능이 더 좋음

### 3.5.2 집계함수

- GROUP BY절을 통해 그룹핑한 후 통계값 계산하는 함수
- COUNT, SUM, AVG, MIN, MAX
- DISTINCT : 컬럼값의 중복제거 즉 해당 그룹에서 첫번째 행에 대해서만 연산 수행

### 3.5.3 HAVING

- WHERE절과 달리 집계함수를 사용할 수 있음
- SELECT JOB, AVG()

## 3.6 ORDER BY절

### 3.6.1 ORDER BY

- 테이블에 삽입된 데이터는 특별한 순서없이 디스크에저장 : 튜플의 무순서성
- DBMS에 따라 NULL값 최소,최대로 처리하는 방식다름

## 3.7 조인

### 3.7.1 조인의 개념

- 두개의 테이블을 하나로 병합하는 것
- O(N^2) 시간복잡도를 가지므로 조회성능을 위해서는 조인이 덜 일어나도록, 반정규화가 필요

### 3.7.2 EQUI JOIN

- Equal(=), 등식을 조건으로 사용할때 발생하는 조인

### 3.7.3 Non EQUI JOIN

- 부등식을 사용해서 범위를 나타낸 조건일때 발생하는 조인

### 3.7.4 3개 이상 TABLE JOIN

- N개의 테이블을 조인할때 N-1번의 조인이 발생함

### 3.7.5 OUTER JOIN

- EQUI, NON EQUIJOIN은 INNER JOIN에 해당, 교집합에 해당한다면
- OUTER JOIN은 조인 조건에 맞지않는 행까지 포괄적으로 병합하는 방법, 합집합에 해당
  - LEFT, RIGHT, FULL등
- 오라클 기준 WHERE A.DEPT NO = B.DEPTNO(+)의 경우
  (+) 기호가 붙지 않은쪽이 기주넽이블이 됨, 즉 A LEFT OUTER JOIN B

## 3.8 표준 조인

- DBMS마다 문법이 약간 달라지는 이슈해결을 위해 표준을 만듬
  - ANSI(미국 국가표준 협회) SQL
  - ISO(국제 표준화 기구)

### 3.8.1 INNER JOIN

- 교집합
- 기준이되는 키에 따른 값이 존재하는 것만 병합

### 3.8.2 OUTER JOIN

- 합집합
- 기준이 되는 키에 따른 칼럼값이 존재하지 않더라도 모든 튜플을 병합
- 어떤 테이블들의 행을 포함시킬지에 따라 LEFT, RIGHT구분

### 3.8.3 NATURAL JOIN

- 두테이블에서 같은 이름의 컬럼들에 대해서 동일한 컬럼값을 가지는 행만 병합되는 조인
- 조인조건을 내포하고있으므로 ON절을 사용할 수 없음, SELEECT 절의 컬럼명에도 테이블 별칭 표시할수 없음

### 3.8.4 CROSS JOIN

- 왼쪽,오른쪽 모든행의 대응을 조합하여 결과를 출력
- 조건이 별도로 지정되지 않음
