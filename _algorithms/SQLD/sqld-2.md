## 2.1 정규화

> 이상현상을 방지하기 위해 데이터 중복을 최소화하면서 테이블을 잘 조직된 상태로 분해하는 과정

- 이상현상(Anomaly) : 테이블과 관계들의 CRUD가 일어나는 과정에서 일관성이 깨지는 현상

### 2.1.1 이상현상 종류

- 삽입이상 : 테이블에 데이터 삽입 시 의도하지 않은 정보까지 삽입해야 하는 현상
- 갱신 이상 : 중복저장되어있는 데이터 중 하나만 갱신하고 다른 하나를 갱신하지 않을때 나타나는 데이터 불일치 현상
- 삭제 이상 : 테이블의 특정 데이터를 삭제할때 의도하지 않은 정보까지 삭제되는 현상

### 2.1.2 정규화 절차 - **도부이결다조**

- 제1 정규화 : 릴레이션의 속성값이 모두 원자값만으로 구성되어야 함
  - 중복값 제거
  - 기본키 설정
- 제2 정규화 : 기본키 2개이상의 속성으로 이루어진 경우 부분 함수종속성을 제거
- 제3 정규화 : 기본키 제외 컬럼간의 종속성 제거, 이행 함수종속성을 제거
- BCNF : 기본키를 제외 후보키가 있는경우 후보키가 기본키를 종속시키면 분해

### 2.1.3 제1정규형

- 모든 속성이 하나의 속성값, 유사한 속성이 반복되지 않는 상태

### 2.1.4 제2정규형

> 부분 함수종속성을 제거한상태

- 부분 함수 종속성이란
  - **주식별자가 2개** 이상으로 구성된 복합식별자의경우, 일반 속성이 주식별자의 일부에만 종속성을 가지는 상황
- 주식별자가 단일식별자일 때는 제2정규화가 필요없으며, 이미 제2정규형인 상태

### 2.1.5 제3정규형

> 이행 함수 종속성을 제거한상태

- 이행 함수 종속성이란
  - 주식별자가 아닌 **일반 속성** 간에 함수종속성이 존재하는상태
  - PK속성 A와 일반속성B,C가있을때 B->C 함수종속성이 존재하면 C는 A에 대해 이행 함수종속성을 가진다고 말함, (A->B는 이미성립하니)

## 2.2 관계와 조인의 이해

### 2.2.1 조인의 트레이드 오프

- 정규화를 통해 분해된 테이블들은 조회 과정에서 여러 번의 조인이 발생가능
- 조인은 DB의 성능 측면에서 다소 부하가 높은 연산, 정규화를 통해 분해된 DB는 조회성능이 떨어질 수 있음
- 성능 저하를 막기위한 조인의 빈도를 줄이는것도 필요
- 데이터의 정합성과 조회성능 간 트레이드 오프 관계 존재

### 2.2.2 반정규화가 필요한 상황

- 조회성능이 중요한 상황
- 반정규화 시 DB정합성이 낮아져 문제가 발생할 수 있으므로 대안을 검토후 반정규화 진행
  - 대안의 종류 (뷰 생성, 인덱스 조정, 클러스터링 적용, 어플리케이션에서의 처리 등)

### 2.2.3 테이블 반정규화

- 테이블 병합

  - 조인의 발생빈도가 높아 여러 테이블을 하나로 합치는 것이 성능 향상에 효율적일때 사용
  - 1:1관계 테이블 병합, 1:M 관계 테이블 병합, 슈퍼타입/서브타입 관계 테이블 병합

- 테이블 분할

  - 테이블의 특정 속성들에 대해서만 집중적으로접근하는 경우 별도의 테이블로 분할
  - 접근 빈도나 잠김 또는 경함 현상이 감소하는 효과가 있으나 분할된 테이블을 전체조회할때는 결국 UNION, JOIN을 사용해야하므로 성능하락이 발생하는점을 감안
  - 수직분할, 수평분할
  - 수직분할 : 특정 속성들에 대해서만 접근이 빈번할때 분할, 로우체이닝 발생시수직분할 우선적 고려
  - 수평분할(파티셔닝) : 속성의 값에 따라서 구분하여 조회, 인스턴스들을 그룹핑하여 나누워 질 수 있도록 분할하는 방법, 분할된 테이블의 스키마는 기존과동일

- 테이블 추가
  - 조회에 필요한 속성을 포함하는 새로운 테이블을 추가, 중복, 통계, 이력, 부분 테이블 추가 방법이 있음
  - 중복 테이블 추가 : 다른 업무나 서버에 있는 테이블과 동일한 구조의 테이블을 중복해서 추가하여 원격 조인을 제거
  - 통계 테이블 추가 : SUM, AVG 등 통계값에 해당하는 연산을 미리 계산하여 저장하는 별도의 테이블을 추가
  - 이력 테이블 추가 : 변경 이력 등 이력 데이터를 관리할 수 있는테이블을 별도로 추가
  - 부분 테이블 추가 : 디스크 I/O를 줄이기 위해 하나의 테이블 내에특별히 자주 사용하는 속성들만 모아서 새로운 테이블로 추가

### 2.2.4 칼럼 반정규화

- 중복 컬럼 추가 : 조인을 감소시키기 위해 자주 사용하는 컬럼을 중복 추가하는 기법
- 파생 컬럼 추가 : 트랜잭선 처리 시 계산에의한 부하발생을 줄이기 위해 계싼값을 별도의 컬럼으로 미리 추가
- 이력 테이블 컬럼 추가 : 대랑의 데이터 처리시, 조회성능 저하를 예방하기 위해 이력테이블에 조회조건에 해당하는 기능성 컬럼 추가
- PK에 의한 컬럼 추가 : 복합 의미를 갖는 PK를 단일 속성으로 구성했을때, PK를 파싱해서 추가적인 내용을 조회해야하는 경우에 성능하락이 존재할 수 있으므로 이를 일반속성으로 추가하는 기법
- 응용 시스템 오동작을 위한 컬럼 추가 : 이전(백업) 데이터를 임시적으로 중복하여 보관하는 기법

### 2.2.5 관계 반정규화

- 여러 관계를 거쳐 다수의 조인을 통해 처리가 가능하지만 이때 발생할 수 있는 성능 저하를 막기위해 추가적으로 중복된 관계를 맺는 방법
- 조인이 많으면 CPU연산 부하가 커짐 -> 조회 성능 저하

## 2.3 모델이 표현하는 트랜잭션의 이해

- DB에 데이터 삽입,수정,삭제할 때, 원자적으로 하나의 단위로 실행되어야 데이터의 정합성이 깨지지 않음
- All or Noting 으로 처리 되어야 함, 트랜잭션 단위로 처리되어야함

### 2.3.1 트랜잭션의 개념

- DB에 데이터를 읽고 쓸때, 한번에 수행되어야 하는 논리적인 작업 단위

### 2.3.2 트랜잭션의 특성 ACID

- 원자성(Atomicity) : 하나의 트랜잭션 All or Nothing
- 일관성(Consistency) : 트랜잭션의 결과는 DB의 정합성을 깨지 않는다는 것으로서 트랜잭션 이전에 DB에 오류가없다면 트랜잭션 이후에도 오류가 없음
- 고립성(Isolation) : 트랜잭션은 독립적으로 수행, 다른 트랜잭션이 실행 중간에 간섭하거나 영향을 미치지 않음
- 영속성(Durability) : 트랜재겻ㄴ의 결과는 DB에 영구적으로 저장되어 유지

### 2.3.3 트랜잭션 격리수준 낮을때 문제점

- Dirty Read : 트랜잭션에 의해 수정되었으나 아직 커밋이 되지않은 상태에서, 다른 트랜잭션이해당 데이터를 읽게 되어 발생하는 데이터의 불일치 현상
- Non-Repeatable Read : 한 트랜잭션 내에서 같은 쿼리를 두번 실행할 때, 그 사이에 다른 트랜잭션이 값을 수정하거나 삭제하면서 첫번째와 두번째 쿼리의 결과가 달라지는 현상
- Phantom Read : 한 트랜잭션 내에서 같은 쿼리를 두번 실행할 때, 그 사이에 다른 트랜잭션이 값을 삽입하면서 두번째 쿼리에서 없던 레코드가 나타나는 현상

### 2.3.4 트랜잭션 격리수준

- 여러개의 트랜잭션을 동시에 처리할 때, 완전하게 락을걸고 실행하면 쓰기작업 중에는 전혀 해당 데이터를 조회하는것이 불가능하므로 조회성능이 매우 낮아질 수 있는 문제 존재
- 쓰기작업 중 읽기작업을 어느 정도로 허용할지를 정할 수 가 있는데 이를 트랜잭션의 격리수준 이라함

## 2.4 Null 속성의 이해

### 2.4.1 Null의 개념

- 속성값을 말할 때 값이 아직 입력되지 않은 상태에 대한 특별한 표현
- Null은 공백, 0도 아닌 아무런 값도 가지고 있지 않은 상태
- 단일행 연산 : 100 + Null = Null
- 다중행 연산 : Null값인 행을 제외하고 연산을 수행, 10,20,Null,30의 평균 -> 20

## 2.5 본질식별자 vs 인조식별자

- 본질식별자 : 업무에 존재하느 원래의 식별자, 원조식별자 라고도 함
- 인조식별자 : 업무에 존재하지 않으나 원래의 식별자가 복잡해서 인위적으로 만든 식별자, 대리식별자 라고도함
